# Sensora design QA checklist (고정)

이 문서는 Sensora의 랜딩/앱/관리자 화면 작업 시 반드시 통과해야 하는 제품·디자인·품질 체크리스트입니다.

## 0) 제품 정체성 확인 (필수)

- [ ] Sensora가 “AI 데모”가 아니라 **프리미엄 자동차 영업 CRM**으로 보이는가
- [ ] 사용자 가치가 `상담 정리 / 다음 연락 / 고객관리 정확도` 중심으로 전달되는가
- [ ] 과장된 AI 표현이 없는가 (`AI가 다 해준다`, `자동으로 처리` 등 금지)

## 1) AI 원칙 준수

- [ ] 자동 저장처럼 보이는 UX/카피가 없는가
- [ ] 자동 발송처럼 보이는 UX/카피가 없는가
- [ ] “사용자 확인 후 저장” 흐름이 유지되는가
- [ ] AI 역할이 정리/제안으로 제한되어 보이는가
- [ ] 최종 판단·발송이 영업사원 직접 수행으로 표현되는가

## 2) 스타일/브랜드 일관성

- [ ] 구 스타일(다크 네이비/네온)과 신 스타일(버건디/크림)이 섞이지 않는가
- [ ] 컬러 토큰 사용이 일관적인가
  - Deep Burgundy `#810B38`
  - Ivory / Cream `#F1E2D1`
  - Beige `#DCC3AA`
  - Deep Brown `#541A1A`
- [ ] 버건디가 CTA/활성/핵심 포인트에만 사용되는가
- [ ] 앱/관리자 화면이 버건디 과다 도포 없이 차분한 업무형 톤인가

## 3) 시각 품질/가독성

- [ ] 텍스트 대비가 충분한가 (버튼/본문/보조텍스트 모두)
- [ ] 카드/배경/라인의 명암 분리가 명확한가
- [ ] 버튼/카드 스타일이 화면마다 제각각으로 보이지 않는가
- [ ] 실제 서비스처럼 완성도 있는가 (데모/테스트 페이지 느낌 제거)

## 4) CTA/모바일 UX

- [ ] 랜딩 첫 화면 CTA가 바로 인지되는가
- [ ] 모바일 첫 화면에서 핵심 카피와 CTA가 잘 읽히는가
- [ ] 버튼 크기와 터치 영역이 충분한가
- [ ] 과한 헤드라인/배경 중첩으로 모바일 가독성이 깨지지 않는가

## 5) 화면별 품질 기준

### 랜딩

- [ ] 3초 내 서비스 이해 가능 구조인가
- [ ] 흐름이 자연스러운가  
  `문제 제기 → 해결 흐름 → AI 상담 정리 예시 → 신뢰 원칙 → 무료 베타 신청`
- [ ] 과장된 AI 연출(마법·자동완성 인상)이 없는가

### 앱

- [ ] 매일 쓰는 업무 도구처럼 보이는가
- [ ] 가독성·입력 편의성·업무 효율이 우선되어 있는가
- [ ] 첫 화면 핵심 흐름이 유지되는가  
  `오늘 할 일 / 빠른 상담 메모 / AI 정리 결과 / 문자 초안 복사 / 다음 연락 저장`

### 관리자

- [ ] 개인정보 기본 목록 마스킹이 유지되는가
- [ ] 관리자 권한 미충족 시 PII가 노출되지 않는가
- [ ] 상태 필터/승인/반려/운영 상태 확인이 명확한가
- [ ] 상태코드 의미가 일관적인가 (`503`, `401`, `403`)

## 6) 보안/신뢰 체크

- [ ] 콘솔/로그에 개인정보 전체값 출력이 없는가
- [ ] 실제 키/관리자 이메일/서비스 계정 JSON이 코드·문서에 하드코딩되지 않았는가
- [ ] 보안 신뢰를 해치는 시각 요소(과도한 장식, 혼란스러운 경고)가 없는가

## 7) 최종 품질 게이트 (릴리즈 전)

- [ ] `npm run build` 통과
- [ ] 보호 경로 미수정 확인
- [ ] `git status` clean 확인
- [ ] 변경 화면(랜딩/앱/관리자)의 모바일 포함 수동 확인 완료

---

운영/권한/환경변수 상세는 `docs/sensora-production-setup.md`를 함께 확인합니다.
